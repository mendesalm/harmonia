# Plano de Implementação: Banco de Dados do Harmonia

Este documento descreve a modelagem de dados proposta para atender aos novos requisitos do sistema Harmonia, com foco na globalidade do acervo, estrutura de ritos/sessões e gestão de assinaturas.

## Proposed Changes

### Modelagem Relacional do Banco de Dados (Tabelas)

Abaixo estão as tabelas principais e seus relacionamentos para suportar as funcionalidades.

#### 1. Gestão de Assinantes
Tabelas para gerenciar as Lojas e os Ritos.

*   **`ritos`**
    *   `id` (PK)
    *   `nome` (Ex: Rito Brasileiro, REAA)

*   **`lojas`**
    *   `id` (PK)
    *   `nome_loja`
    *   `numero_loja`
    *   `rito_id` (FK -> `ritos.id`)
    *   `endereco`
    *   `validade_assinatura` (Data)
    *   `status_assinatura` (Ativo, Vencido)

#### 2. Eventos e Tipos de Sessão (Templates Globais)
Tabelas que armazenam a estrutura base das sessões, permitindo que o sistema sugira a montagem caso a Loja não tenha nada cadastrado.

*   **`eventos_ritualisticos`**
    *   `id` (PK)
    *   `nome` (Ex: "Tronco de Beneficência", "Entrada do Pavilhão Nacional")
    *   *Nota:* Para a equivalência entre ritos, usaremos nomes padronizados aqui. Se dois ritos usam o mesmo evento, eles apontarão para o mesmo ID no banco, facilitando a sugestão global de músicas.

*   **`tipos_sessao`**
    *   `id` (PK)
    *   `nome` (Ex: Sessão Ordinária, Sessão Magna de Iniciação)
    *   `rito_id` (FK -> `ritos.id`)

*   **`tipos_sessao_eventos`** (Tabela de ligação que define o roteiro/ordem do template)
    *   `id` (PK)
    *   `tipo_sessao_id` (FK)
    *   `evento_id` (FK)
    *   `ordem_sequencia` (Inteiro: 1, 2, 3...)
    *   `momento_silencio` (Boolean: Indica se normalmente é um momento sem música)
    *   `observacao_padrao_mestre_harmonia` (Texto: Orientação sugerida globalmente para o evento, ex: "Aguardar o Posicionamento do Porta Bandeiras...")

#### 3. Acervo Global (Músicas)
Tabela central para todas as músicas que sobem para o servidor.

*   **`acervo_musicas`**
    *   `id` (PK)
    *   `titulo`
    *   `arquivo_url`
    *   `upload_por_loja_id` (FK -> `lojas.id`, rastreia quem subiu. Pode ser nulo se upado pelo Superadmin)
    *   `sinalizada_erro` (Boolean: true se alguém reportou problema)
    *   `status_uso` (Enum: `ATIVA`, `ORFA`)

*   **`acervo_musicas_eventos_sugeridos`** (Relaciona a música aos momentos ritualísticos indicados no momento do upload)
    *   `id` (PK)
    *   `musica_id` (FK -> `acervo_musicas.id`)
    *   `evento_id` (FK -> `eventos_ritualisticos.id`)

#### 4. Instâncias da Loja (O que a Loja customiza/usa)
Quando uma loja monta sua sessão, ela cria instâncias próprias baseadas nos templates. Para permitir total flexibilidade, a loja copia os eventos do template para poder reordená-los, suprimi-los ou adicionar orientações.

*   **`sessoes_loja`**
    *   `id` (PK)
    *   `loja_id` (FK -> `lojas.id`)
    *   `tipo_sessao_id` (FK -> `tipos_sessao.id`)
    *   `nome_personalizado` (Opcional)

*   **`sessoes_loja_eventos`** (O Roteiro Customizado da Loja)
    *   `id` (PK)
    *   `sessao_loja_id` (FK -> `sessoes_loja.id`)
    *   `evento_id` (FK -> `eventos_ritualisticos.id`)
    *   `ordem_execucao` (Inteiro. Permite à loja mudar a ordem padrão do template)
    *   `suprimido` (Boolean, default false. Permite à loja ocultar um evento que não realiza)
    *   `observacao_mestre_harmonia` (Texto. Inicialmente preenchido com a orientação padrão do template, mas a loja pode editar com suas próprias orientações)

*   **`playlists_loja`** (As músicas atreladas aos eventos da loja)
    *   `id` (PK)
    *   `sessao_loja_evento_id` (FK -> `sessoes_loja_eventos.id`)
    *   `musica_id` (FK -> `acervo_musicas.id`)
    *   `ordem_musica` (Inteiro, caso haja mais de uma música no mesmo evento)

## Lógica de Negócios (Backend)

1.  **Exclusão/Edição de Música:** 
    Ao tentar deletar/editar uma música, o backend fará um `SELECT COUNT(*) FROM playlists_loja WHERE musica_id = X`. Se o resultado for maior que 0 (e não for exclusivo da loja que pediu a exclusão), a ação é bloqueada.
2.  **Identificação de Arquivos Órfãos (Rotina CRON):**
    Uma rotina periódica (CRON Job / Background Task) no backend verificará quais `acervo_musicas.id` não existem na tabela `playlists_loja`. Essas músicas terão seu `status_uso` alterado para `ORFA`, aparecendo em um dashboard exclusivo do Superadmin para decisão de exclusão física do servidor.
3.  **Sugestão Inteligente (Auto-Fill):**
    Quando a Loja não tiver playlist para uma sessão nova, o sistema copiará os eventos da tabela `tipos_sessao_eventos` para `sessoes_loja_eventos`. Em seguida, buscará quais são as músicas (`musica_id`) mais associadas àquele `evento_id` por outras lojas, e preencherá a `playlist_loja` com esses resultados.

## Painel do SuperAdmin

O sistema contará com uma área administrativa exclusiva (SuperAdmin) para a gestão centralizada da plataforma. As principais funcionalidades (formulários) incluem:

1.  **Cadastro de Eventos Ritualísticos:** Formulário para criar os eventos globais (ex: "Entrada do Pavilhão Nacional", "Tronco de Beneficência"), preenchendo o nome e a observação padrão para o Mestre de Harmonia.
2.  **Montagem de Tipos de Sessão por Rito:** Formulário onde o SuperAdmin seleciona um Rito, cria um Tipo de Sessão (ex: "Sessão Magna de Iniciação") e arrasta/seleciona os Eventos Ritualísticos na ordem correta, gerando o template global (`tipos_sessao_eventos`).
3.  **Upload de Músicas no Acervo:** Formulário para envio de arquivos de áudio. É **obrigatório** que, durante o upload, o SuperAdmin (ou a Loja) selecione em um *checklist* de múltipla escolha quais são os **momentos ritualísticos sugeridos** para aquela música (populando a tabela `acervo_musicas_eventos_sugeridos`).
4.  **Gestão de Lojas e Assinaturas:** Controle de ativação, renovação e bloqueio de clientes.
5.  **Análise de Arquivos:** Dashboard para verificar músicas sinalizadas com erro pelos usuários ou marcadas como "Órfãs" (sem uso) pela rotina do sistema.
